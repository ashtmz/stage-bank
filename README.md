# 舞台用語ライブラリ

舞台・劇場、音響、照明、映像・制御、制作・運営、安全・仕込み、衣裳・メイク、楽器・音楽、電源・通信を調べるブラウザ用ライブラリです。一般用語に加え、技術、機材、機種・ソフト固有の機能も収録します。

## 使う

`起動.command` をダブルクリックすると、この端末内で起動してブラウザを開きます。停止は起動したターミナルで Control + C。

ターミナルからはこのフォルダで `npm run dev` を実行し、ブラウザで <http://127.0.0.1:5173/> を開きます。初回の依存関係の準備は `npm install` です（この環境では実施済み）。

配布用ファイルは `npm run build` で `dist/` に作成できます。確認は `npm run preview`（<http://127.0.0.1:4173/>）。`dist/index.html` の直接ファイル起動ではなく、HTTP サーバーで配信してください。

## GitHub Pagesで公開する

公開先リポジトリは [ashtmz/stage-bank](https://github.com/ashtmz/stage-bank)。初回設定後は、公開URLを開くだけで利用でき、閲覧用のコマンド操作やローカルサーバーの起動は不要です。

1. GitHubのプランを確認します。GitHub Freeでは公開リポジトリ、GitHub Pro等では非公開リポジトリでもPagesを利用できます。リポジトリの公開範囲は必要に応じて所有者が選択します。
2. リポジトリの [Settings → Pages](https://github.com/ashtmz/stage-bank/settings/pages) で、Build and deployment の Source を **GitHub Actions** にします。
3. このフォルダの公開用設定 `.github/workflows/pages.yml` と README の変更を `main` にコミットし、GitHubへ送ります。GitHub Desktopなら Commit → Push origin で操作できます。Pages設定を有効にする前に送った場合は、[Actions](https://github.com/ashtmz/stage-bank/actions) の **Publish to GitHub Pages → Run workflow** から実行します。
4. Actionsの公開完了後、`https://ashtmz.github.io/stage-bank/` を開きます。更新履歴は `https://ashtmz.github.io/stage-bank/#update=latest` です。

公開時はデータ検証・テストを実行し、成功したものだけを `/stage-bank/` 向けにビルドします。アップロード対象は `dist/` のみです。以後、`main` へ送った変更は同じ手順で自動再公開されます。

このチャットの月次更新はローカルの用語データと更新インデックスを編集します。公開サイトへ反映するには、その変更もGitHubへ送る必要があります。ローカル画面と公開サイトの保存済み用語・メモは別の保存先になるため、移行する場合は「データ」から書き出し・読み込みを使います。

設定の根拠：[GitHub Pagesの公開元](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[ViteのGitHub Pages手順](https://vite.dev/guide/static-deploy.html#github-pages)。

## 探す・残す

- 左側の分野を選び、「小分類」で場所・機材・作業などに絞り込みます。
- 日本語、読み、英語、略語、別名、説明から検索できます。半角・全角やカナの違いを吸収し、空白区切りは AND 検索です。`/` で検索欄へ移動します。
- 日本・米国・英国・欧州は、語の使用地域による絞り込みです。共通の語はいくつかの地域に表示されます。欧州欄は国・言語を明記し、全欧州共通の呼び方とはしません。
- 用語ごとの保存、メモ、追加した用語の編集・削除ができます。
- 「データ」から保存済み・追加用語・メモを JSON 形式で書き出し、読み込めます。取り込みは追加方式で、重複する ID の内容は現在の編集を残します。
- 保存先はこのブラウザのローカルストレージです。別のブラウザや端末とは自動同期しません。ブラウザのデータを消す前にバックアップを書き出してください。URL のホストやポートが変わると保存先も変わります。

## 収録データ

現在の件数は画面の表示と [更新インデックス](docs/updates/README.md) で確認できます。分野ごとに小分類を設け、さらに「用語／技術／機材／機能」で絞り込めます。

| 分野 | 主な対象 |
|---|---|
| 舞台・劇場 | 劇場、位置、伝統舞台、幕、大道具、小道具、機構、素材、転換 |
| 音響 | 拡声、収音、卓、信号処理、測定、ワイヤレス、空間音響、音声ネットワーク |
| 照明 | 灯体、光学、色、照射位置、卓、制御信号、プログラム、演出 |
| 映像・制御 | 投影、LED、色、カメラ、コーデック、IP 映像、送出、ショー制御 |
| 制作・運営 | 稽古、進行、図面、ツアー、アクセシビリティ、担当範囲 |
| 安全・仕込み | 搬入、設営、吊り、荷重、安全管理 |
| 衣裳・メイク | 衣裳製作、素材、早替え、かつら、メイク、管理 |
| 楽器・音楽 | 楽器、編成、譜面、音楽稽古、オペラ・バレエ |
| 電源・通信 | IP、同期、ネットワーク管理、配線、接続部品、給電・配電 |

拡充した項目では「仕組み・概要」「使う場面」「違い・注意点」を確認できます。機材や固有機能は、確認できたメーカー、バージョン、仕様を掲載し、資料の確認日を発表日とは別に表示します。公式ページに掲載された既存製品を、新発売とは扱いません。

用語の意味は独自に要約しています。各項目の「出典・参考」に、確認した公開資料へのリンクがあります。日本の慣用語と英語の近似表現は、必要な箇所で一対一対応ではない旨を記載しています。舞台の左右は、上手＝客席から右＝Stage left、下手＝客席から左＝Stage right として図示しています。

主な資料：日本芸術文化振興会、昭和音楽大学、劇場・大学の教育資料、Yamaha、Shure、ETC、ESTA、Rosco、LEE、Blackmagic Design、Figure 53、EIZO、HSE、メーカーの公式資料等。詳細は `docs/*-sources.md` と各データ項目を参照してください。

収録範囲は網羅を保証するものではありません。地域・劇場・職域で意味が変わる語は、各項目の補足を確認してください。

## 更新・確認

データは `src/data/*.json`、項目形式は `src/data/schema.md` です。同じ名称でも分野によって意味が異なる項目は、分野を表示して区別しています。単なる別名は aliases にまとめます。

`npm test` で検索・復元処理のテスト、`npm run check:data` で ID・必須項目・関連語・方向の整合性、`npm run build` で配布用ビルドを確認します。

## 定期更新とインデックス

毎月1日9:00（日本時間）に、このチャットの Codex 定期タスクで調査・更新します。メーカー公式発表、正式リリースノート、公開マニュアル、規格団体・劇場・大学の一次資料を確認します。調査先と編集手順は [WATCHLIST](maintenance/WATCHLIST.md) と [UPDATE_WORKFLOW](maintenance/UPDATE_WORKFLOW.md) に記載しています。

画面の「更新履歴」で、日付ごとの追加・変更・整理、変更した情報の種類、参考資料を確認できます。項目名から現在の用語説明へ移動できます。履歴は JSON と Markdown の両方で残します。

内容を更新する際は、検証後に `npm run index:update -- --title '更新の題名' --summary '具体的な変更点'` を実行します。実際の差分からインデックスを作り、確認日だけの変更や、変更のない再実行では履歴を増やしません。過去の項目名と説明も当時の記録として保持します。

ローカルファイルを更新する定期タスクのため、実行時には Mac と Codex アプリを稼働させ、対象フォルダとウェブを利用できる状態にしてください。[公式説明](https://learn.chatgpt.com/docs/automations?surface=app)
